# `docs/` — visual documentation

Standalone HTML reports, same pattern as the ADNI / CardioGraph
projects: one self-contained file per document, embedded CSS, no
build step. Open in any browser. Print to PDF for offline study.

## What's here

| File | What it is |
|---|---|
| [`curriculum.html`](curriculum.html) | The zero-to-hero study guide. Tier-by-tier lesson map, the stack table, quick-start, glossary, references. Read this first. |
| [`architecture.html`](architecture.html) | Module map, the switchable-provider adapter pattern, agent-middleware onion, capstone architecture diagrams, supervisor-vs-swarm and persistence comparisons. |

Both files cross-link to the per-lesson and per-capstone Markdown
READMEs in `lessons/` and `projects/`.

## Open them

Just double-click the file in your file explorer, or:

```bash
# macOS / Linux
open docs/curriculum.html

# Windows
start docs/curriculum.html
```

There is **no web server** involved. The files are pure HTML +
inline CSS + Google Fonts via CDN.

## Print / share

Browsers print these well — `Cmd/Ctrl+P` → "Save as PDF" gives you
a clean offline copy. Share that PDF with anyone who wants the
curriculum overview without cloning the repo.

## Add another doc

Match the visual style of the existing two:

1. Copy `curriculum.html` to `docs/your_topic.html`
2. Strip the body, keep the `<style>` block (or extract it to a
   shared snippet if you make several)
3. Add a `<a href="your_topic.html">` link from the top-level
   [README](../README.md) and from `architecture.html`'s top nav

The CSS variables at the top of each file are the design tokens:
change them once to re-theme.

## Why HTML and not Sphinx / MkDocs / Docusaurus?

Same reason ADNI and CardioGraph went this way: **zero build step,
one file, one click to open**. A learner doesn't need to install
anything. The repo cloned in 2030 will still render exactly the
same. Trade-off: no autogenerated API docs — if you ever want
those, drop in MkDocs alongside, don't replace these.
