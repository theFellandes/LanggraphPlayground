01 · MAP

Module layout

Three top-level packages and a small shared/ kernel. Lessons import only from shared/; capstones occasionally cross-import.

02 · PATTERN

Switchable LLM provider layer

A small factory plus one file per provider. The same pattern used in larger multi-provider systems (Mitrailleuse, Aletheia). Lessons never see a provider SDK directly.

The flow

.env  LLM_PROVIDER=openai
        │
        ▼
shared/settings.py      ──►  settings.llm_provider == "openai"
        │
        ▼
shared/llm/base.py      ──►  get_llm()
        │                              │
        │                              ▼
        │                       _ADAPTERS["openai"](model=None)
        │                              │
        ▼                              ▼
   # lesson code           shared/llm/openai_adapter.py
   llm = get_llm()                   build() ──►  ChatOpenAI(...)
   llm.invoke("hi")

Adding a new provider in 4 steps

1. install     uv add langchain-google-genai
2. adapter     shared/llm/google_adapter.py:
                  def build(model=None, **kw):
                      return ChatGoogleGenerativeAI(
                          model=model or "gemini-2.0-flash",
                          google_api_key=settings.google_api_key,
                          **kw)

3. settings    add `google_api_key: str | None = None` to Settings

4. register    shared/llm/base.py:
                  _ADAPTERS = {
                      "anthropic": anthropic_adapter.build,
                      "openai":    openai_adapter.build,
                      "google":    google_adapter.build,  ← new
                  }

No lesson code changes. The change is purely additive — the existing two providers still work.

03 · ONION

Agent middleware lifecycle

Middleware wraps create_agent in onion-style layers. The outermost before_agent runs first; the innermost wrap_model_call/wrap_tool_call runs last (closest to the actual model/tool). After is symmetrical, in reverse.

before_agent   ·   after_agent
runs once per agent run
before_model   ·   after_model
runs once per model call
wrap_model_call
full control: you call handler(request)
wrap_tool_call
full control: you call handler(call)
⚙ model / tool ⚙

Custom middleware = subclass AgentMiddleware

class CostGuardrail(AgentMiddleware):
    def __init__(self, max_calls=5):
        self.max_calls = max_calls
        self.calls = 0

    def wrap_model_call(self, request, handler):
        self.calls += 1
        if self.calls > self.max_calls:
            raise RuntimeError("budget exceeded")
        return handler(request)

agent = create_agent(model=..., tools=[...],
                     middleware=[CostGuardrail(max_calls=5)])

07 · COMPARE

Supervisor vs swarm

SUPERVISOR (star)              SWARM (mesh)
─────────────────              ─────────────────
       user                          user
        │                              │
        ▼                              ▼
   supervisor                       triage  ◄──┐
   ┌────┼────┐                        │        │
   ▼    ▼    ▼                     handoff     │  handoff
  W1   W2   W3                        │        │  back
                                      ▼        │
                                   refunder ───┘
+ central control                + zero supervisor hops
+ one prompt to maintain         + lower cost per request
− extra LLM hop per delegation   − routing logic distributed
SupervisorSwarm
Topology Star — boss in the middle Mesh — peers
Routing One LLM decides every hop Each agent decides when to hand off
Debug Easy — one place to look Harder — handoffs distributed
Extra LLM hops One per delegation Zero
Best when You want central control or a stable boss2–3 agents own different phases of work
Package langgraph-supervisor langgraph-swarm
08 · COMPARE

Checkpointer choices

CheckpointerWhen to useTrade-off
MemorySaver Dev, demos, tests Lost on process exit
SqliteSaver Local single-process apps, CLIs Slow under high write concurrency
PostgresSaver Production web apps, multi-process Needs a Postgres alongside
AsyncPostgresSaverProduction async apps (FastAPI, etc.) Same as above; requires --extra api
Swap rule The graph definition doesn't change. Only the argument to .compile(checkpointer=…) differs. Test with MemorySaver, ship with PostgresSaver.
09 · COMPARE

Streaming modes

stream_mode=Chunk shapeBest for
values Full state dict after each step Demos, dashboards
updates {node_name: partial_update}Server-sent events, bandwidth-sensitive UIs
messages (AIMessageChunk, metadata) Chat UIs — token-by-token
custom Whatever you writer(...) Progress bars, telemetry from inside nodes
astream_events("v2")Per-Runnable lifecycle event Deep debugging, custom UIs
Tip You can pass stream_mode=["updates", "messages"] and chunks come back tagged with their mode. That's how the rag_qa_api capstone could surface both per-node JSON and per-token text in one stream.
